# План приведения АРМАДА к законодательству (рабочий)

**Не заменяет юриста.** Черновики в `web-preview/legal-transport.html` — на утверждение.

## Зачем вообще

| Риск без плана | Что даёт план |
|----------------|---------------|
| Клиент с order.html думает, что согласился на «перевозку», а видит только политику **SaaS** | Отдельные условия **услуг перевозки/подачи ТС** и ПДн под заявку |
| Штрафы/остановка за **высоту > 4 м** без предупреждения | Подсказка с **ПП № 2200**, прил. № 1 |
| Экспедиция и **третьи лица** не отражены в договорах | Явные роли: Армада организует, перевозчик — партнёр |
| Логист кликает **PDF**, файлов нет | HTML-версии + README для юридических PDF |
| Заявка на бумаге **не по прил. 5** к № 2200 | Поэтапно в `DOCUMENTS_PLAN.md` |

---

## Этап 1 — Сейчас (в репозитории)

1. **`legal-transport.html`** — условия заявки на транспорт + ПДн для order.html (отдельно от SaaS).
2. **`order.html` / `order-public.js`** — галочка согласия, ссылки на transport-legal; вес/габариты в заявку; **предупреждение 4 м**.
3. **`store.js`** — высота пола кузова по типу ТС, функция проверки суммарной высоты.
4. **`admin.js`** — баннер в карточке заявки при превышении 4 м.
5. **`web-preview/legal-pdf/README.md`** (заметка для юриста; если папка недоступна — см. подсказку в **`admin-docs.js`**) + ссылки «На сайте», если PDF нет.
6. **`legal/PLAN_COMPLIANCE.md`** (этот файл) + обновление **`INDEX.md`**.

## Этап 2 — Юрист (вне кода)

1. Утвердить текст `legal-transport.html`.
2. Решение по **87-ФЗ** (реестр экспедиторов).
3. Договор с **партнёром-перевозчиком**; шаблон для клиента B2B.
4. Выложить **7 PDF** в `web-preview/legal-pdf/`.

## Этап 3 — Продукт (после «ок» на этап 2)

1. Портал `/z/` — согласие как на order.html.
2. Поля **негабарит / номер разрешения** в заявке и печати (прил. 5, п. 10(2)).
3. Закрытие ⬜ в `DOCUMENTS_PLAN.md` (доверенности, ДОПОГ и т.д.).

## Этап 4 — Staging → проверка Евгения → prod

По `scripts/STAGING.md`, без prod без «ок на prod».
