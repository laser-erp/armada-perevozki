# Заявка в виде чата — предложение для Евгения

> Исследование, не замена текущей формы. Актуально на 28.08.2026.

## Текущая форма (кратко)

Портал заказчика «Новая заявка» — **5 блоков** + **боковой чеклист**:

| Шаг | Блок | Что заполняется |
|-----|------|-----------------|
| 1 | Груз | Описание, места, объём, упаковка, хрупкий/температура, габариты, вес |
| 2 | Когда | Дата (календарь) и время подачи ТС |
| 3 | Маршрут | Адреса загрузки/выгрузки, контакты, карта, км, тип перевозки |
| 4 | Транспорт | Панель типов кузова (ATI), способы загрузки/выгрузки |
| 5 | Условия и цена | Логист/свой парк, бронь машины, ориентир цены, отправка |

Обязательно для отправки: **дата+время**, **оба адреса**, **тип ТС**, **описание груза**, **вес**.

---

## A. Как это могло бы выглядеть

Экран как **переписка с ботом АРМАДА** (не WhatsApp/Telegram — внутри портала):

- Сверху: «Новая заявка · ООО «Армада»»
- Бот задаёт **один вопрос за раз** — пузырь слева (серый/зелёный фон АРМАДА)
- Ответ пользователя — пузырь справа (синий)
- Под вопросом — **кнопки-чипы** для частых ответов (быстрее, чем печатать)
- Внизу — поле ввода + кнопка «Отправить» (как в мессенджере)
- Прогресс: «Шаг 3 из 7» или тонкая полоска

### Пример диалога (одна заявка)

```
🤖 АРМАДА: Здравствуйте! Оформим заявку на перевозку. Что нужно перевезти?

👤 Паллеты с оборудованием, 8 мест, около 3 тонн

🤖 Понял: паллеты, 8 мест, ~3 т. Когда подать машину?

   [Завтра] [Послезавтра] [Выбрать дату…]

👤 Завтра, 9:00

🤖 Откуда забираем груз?

👤 Москва, ул. Складская, 12

🤖 Куда везём?

👤 Подольск, ул. Заводская, 5

🤖 ≈ 42 км, пригород. Какой кузов нужен?

   [Тент] [Фургон] [Рефрижератор] [Другой…]

👤 Тент

🤖 Ориентир: 18 500 ₽ (без НДС). Подтвердите или измените цену.

   [18 500 ₽ — отправить] [Изменить цену] [Логисту — срочно]

👤 18 500 ₽ — отправить

🤖 ✅ Заявка отправлена! Диспетчер свяжется с вами.
```

Сложные шаги (адрес, дата, тип ТС) — **не свободный текст**, а **встроенный виджет** внутри чата: поле адреса, мини-календарь, 3–4 крупные кнопки типов кузова.

## B. Плюсы для заказчика

| Плюс | Пояснение |
|------|-----------|
| **Проще «с нуля»** | Не видно 40 полей сразу — один вопрос, один ответ. Меньше страха «я что-то не так заполнил». |
| **Как мессенджер** | Привычно с телефона; не нужно искать блок «3. Маршрут» на длинной странице. |
| **Мобильный экран** | На узком экране чат занимает всю высоту; не нужен sidebar-чеклист. |
| **Подсказки по ходу** | Бот может объяснить «что такое тент» или «зачем вес» в момент вопроса. |
| **Повторные клиенты** | «Как в прошлый раз?» — одна кнопка подставляет маршрут и тип ТС. |

## C. Минусы и риски

| Минус | Пояснение |
|-------|-----------|
| **Медленнее для опытных** | Кто знает форму и заполняет 10 заявок в неделю — 7 шагов чата дольше, чем пробежать по блокам. |
| **Нет «картины целиком»** | Сложно увидеть и поправить адрес, не листая историю на 5 экранов вверх. |
| **Сложные поля** | Панель типов ТС (кузов + 12 способов загрузки) в чат не влезает красиво — нужен отдельный экран или «развернуть детали». |
| **Цена и НДС** | «18 500 без НДС / с НДС» — в чате легко перепутать; нужна явная карточка-сводка перед отправкой. |
| **Разработка** | Свободный текст («завтра утром к Иванову») без ИИ = ошибки; без ИИ = только кнопки и поля. |
| **Два интерфейса** | Если оставить и форму, и чат — поддерживать два UX. |

## D. Гибридный вариант (часто лучший)

**Рекомендуемая схема для АРМАДА:**

1. **По умолчанию — текущая форма** (уже сделана, чеклист, карта, цена).
2. **Опция «Помощник»** — кнопка «Оформить в чате» для новичков и мобильных.
3. **Чат собирает базу** → в конце **карточка-сводка** (как чек перед оплатой):
   - все поля видны разом;
   - «Изменить» открывает нужный блок формы или шаг чата;
   - «Отправить» — тот же `buildCustomerDraftFromForm()`.
4. **Повтор заказа** — «Как заявка №123» → сразу сводка, правка одного поля.

Так опытные не теряют скорость, новички получают «мессенджер», а сложные поля (транспорт, цена) остаются на **экране подтверждения**, а не в 15-м сообщении.

## E. Что реально для АРМАДА

### MVP без ИИ (скриптовый бот)

- Фиксированная цепочка вопросов (7–9 шагов).
- Ответы: **кнопки + обычные поля** (адрес, дата, число) — без распознавания «перевези завтра паллеты к Петрову».
- Данные пишутся в **те же скрытые поля** или объект заказа → вызывается существующий `buildCustomerDraftFromForm()` / отправка.
- Карта и км — после двух адресов, как сейчас (`refreshCustomerRouteKm`).
- Цена — после маршрута и веса, как `updateCustomerPricePreview`.

### Что меняется в коде (оценка объёма)

| Компонент | Изменения |
|-----------|-----------|
| `index.html` | Новая секция/экран чата ИЛИ отдельная страница превью; переключатель «Форма / Чат» |
| `customer.js` | Модуль `customerChatWizard`: state machine шагов, рендер пузырей, запись в поля формы |
| `styles.css` | Стили чата (~150–250 строк): пузыри, чипы, прогресс |
| `store.js` / отправка | **Без изменений** — тот же draft и API |
| Сложный транспорт | Упрощённый шаг в чате (тент/фургон/реф/борт) + «Подробнее → форма» |
| Тесты / онбординг | Обновить подсказки в `onboarding.js` |

**Объём:** средний — новый UI-слой поверх существующей логики, не переписывание заявки с нуля. Основная работа — **state machine + мобильная вёрстка + экран сводки**. Панель ATI-типов в чате полностью не дублировать.

### Свободный текст + ИИ

- Отдельный этап: парсинг адресов, дат, веса → дорого и ненадёжно для MVP.
- Для одного перевозчика и повторных B2B-клиентов **не обязательно**.

## Рекомендация

**Для вашего кейса (один перевозчик, постоянные заказчики, не клон ATI):**

| Вариант | Вердикт |
|---------|---------|
| Полная замена формы на чат | ❌ Не стоит — потеряете скорость опытных и удобство правки |
| Чат с ИИ и свободным текстом | ❌ Пока рано — лишняя сложность и риск ошибок |
| **Гибрид: форма + опциональный чат-помощник + сводка** | ✅ Имеет смысл **после** стабилизации текущей формы на проде |
| Статичное превью для обсуждения | ✅ Сделано: `web-preview/customer-form-chat-preview.html` |

**Практичный порядок:**  
1) довести текущую блок-форму (мобильный чеклист уже есть);  
2) если заказчики жалуются «не понимаю с телефона» — добавить **короткий чат на 5–6 шагов** с финальной карточкой;  
3) не трогать логику цены, маршрута и отправки — только новый «фасад».
