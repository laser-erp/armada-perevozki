## 1. Что именно делает ATI (по открытым источникам)

### 1.1 ATI.SU MCP — основной официальный ИИ-продукт ATI

**Источник:** https://ati.su/developers/raw/atisu-mcp.md  
**Endpoint:** `https://api.ati.su/gw/panda-mcp/public/v1/mcp`

Это **не UI-кнопка на сайте**, а **MCP-сервер для внешних LLM-агентов** (Cursor, Claude Code, VS Code, СуперИнтеллект и т.д.).

#### Как работает сценарий «Добавь груз…»

| Шаг | Что делает пользователь | Что делает система |
|-----|-------------------------|-------------------|
| 1 | Пишет фразу: «автошины из Санкт-Петербурга в Краснодар, загрузка сегодня, 1 т» | Агент вызывает `prepare_cargo_draft` с бизнес-полями из текста |
| 2 | При нехватке данных — один уточняющий вопрос (напр. адрес в СПб) | Runtime сам резолвит города, `TypeId` кузова, контакт; не спрашивает ID словарей |
| 3 | Проверяет карточку-preview | Показывает маршрут, дату, груз, вес, кузов, оплату, assumptions |
| 4 | Подтверждает «да» | `publish_entity_write` → POST в API ATI → read-back |
| 5 | (опционально) «Сколько стоит?» | `estimate_rate_for_cargo` по опубликованному грузу |

#### Пример входа (из документации ATI)

```json
{
  "request": {
    "from_location": {"query": "Санкт-Петербург"},
    "to_location": {"query": "Краснодар"},
    "loading_date": "YYYY-MM-DD",
    "cargo_name": "Автошины",
    "weight_t": 1
  }
}
```

Runtime **сам** подставляет defaults (например `body_type=tent`), сопоставляет со словарями ATI — пользователь не выбирает ID вручную.

#### Какие поля разбираются

Из SKILL.md и entity workflow ATI MCP:

- **Маршрут:** города/адреса загрузки и выгрузки (`from_location`, `to_location`)
- **Дата/время:** `loading_date`, режим загрузки
- **Груз:** название, вес (`weight_t`), объём
- **Транспорт:** тип кузова (`body_type` → `TypeId` из словаря)
- **Оплата:** ставка, НДС, режим оплаты
- **Контакт, площадка, видимость** — подтягиваются server-side или уточняются одним блоком вопросов

#### UI-паттерн

- **Внешний чат** (агент в Cursor / СуперИнтеллект / Claude), **не** sidebar внутри формы ATI
- **Preview-карточка + одно подтверждение** перед записью
- **Не** пошаговый wizard с chips (как наш chat-preview)

#### Технология

- **LLM-агент** + **структурированные MCP-tools** (`prepare_cargo_draft`, `list_dictionaries`, `publish_entity_write`)
- Не «regex-only»: сервер ATI нормализует draft, валидирует по OpenAPI, резолвит словари
- Bearer-токен ATI для записи; discovery без токена

#### Доступность

- Документация и MCP — **публично** на ati.su/developers
- Нужен **аккаунт ATI + OAuth/Bearer-токен** для публикации
- Часть сценариев (средние ставки, расширенная статистика) — **платные лицензии ATI**
- Beta/закрытый доступ в help не упоминается — это developer-facing API

### 1.2 СуперИнтеллект × ATI.SU (август 2026)

**Источник:** https://superintellect.ru/blog/integraciya-ati-su

| Пользователь пишет | Агент делает |
|--------------------|--------------|
| «Грузы Москва → Казань на неделю» | Показывает грузы |
| «Размести мой груз 20 тонн» | Создаёт заявку |
| «Размести груз: Москва → Казань, 20 тонн, тент, загрузка в пятницу» | Создаёт заявку (отдельное разрешение) |

- **UI:** чат СуперИнтеллекта, не форма ATI
- **Подключение:** OAuth access_token из кабинета ATI (~2 ч жизни) или client_id/refresh
- **Права:** чтение по умолчанию; размещение грузов — отдельный переключатель
- **Технология:** внешний LLM + API/MCP ATI (ATI официально не реализует UI, только API)

### 1.3 4Logist Navi — частый источник путаницы «ИИ на ATI»

**Источники:**
- https://zen.ati.su/article/2024/10/16/... (ATI публикует кейс на Дзен)
- https://www.4logist.ru/navi-ai/

**Navi — это ИИ внутри CRM 4Logist, не внутри ATI.**

| Что делает | Как |
|------------|-----|
| Принимает текст, PDF, письмо, сообщение клиента | LLM извлекает сущности |
| Заполняет форму заявки в CRM | Адреса, компании, груз, даты |
| Публикует на ATI.SU | «В один клик» на биржи: ATI, Lardi, Trans.eu и др. |

Цитата из материала ATI (Дзен, окт 2024): менеджер **выделяет фрагмент текста**, Navi переносит данные в форму; достаточно проверить и отправить на ATI за секунду.

**Вывод:** Evgeny мог видеть демо 4Logist или статью ATI о партнёре — это выглядит как «ИИ на ATI», но реализовано **снаружи** через CRM + API.

### 1.4 Что ATI делает БЕЗ ИИ (классическая автоматизация)

## 3. Варианты для АРМАДА

### Вариант A — MVP: «Вставить текст → разобрать в поля» ✅ рекомендуем

**UX:**
- Кнопка «Заполнить из текста» над формой (или в блоке 1)
- Textarea: вставка SMS, письма, WhatsApp
- Кнопка «Разобрать» → поля формы заполняются → пользователь проверяет и отправляет

**Что парсить (минимум):**
- Откуда / куда (город + адрес если есть)
- Дата и время подачи
- Описание груза, вес (т/кг), места
- Тип кузова (маппинг на наши 13–17 типов + `ati-body-types.json`)
- Цена если указана

**Технически:**
- **Backend:** один endpoint `POST /api/parse-order-text` → LLM (structured output JSON schema) или гибрид regex + LLM
- **Frontend:** ~50–100 строк — вызов API, маппинг в существующие поля формы (переиспользовать `customerChatApplyToForm` логику)
- **Без** полноценного чат-UI, без streaming, без multi-turn (кроме «не хватило адреса — покажи alert»)

**Сложность:** средняя  
- Backend + API-ключ LLM + промпт/schema: основной объём  
- Frontend: малый (форма уже есть)  
- Словари кузовов: уже частично готовы  

**Риски:** галлюцинации LLM → обязательный preview/ручная правка; адреса без геокодера — только текст в поле.

---

### Вариант B — Полный ATI-like ассистент (чат + MCP-подобный flow)

**UX:** переключатель «Форма / Чат с ИИ», диалог, уточнения, preview, отправка.

**Технически:**
- Stateful chat session на backend
- Tool-calling или staged wizard с LLM на каждом шаге
- Геокодинг, расчёт km, ориентир цены (как ATI `estimate_rate`)
- Подтверждение перед submit

**Сложность:** высокая (в 3–5× больше MVP)  
- По сути мини-MCP для одной формы АРМАДА  
- Нужен backend, хранение сессий, мониторинг ошибок LLM  

**Имеет смысл** только если заказчики реально просят «как в мессенджере»; сейчас chat-preview уже есть без ИИ — можно нарастить позже.

---

### Вариант C — Пропустить

**Аргументы:**
- Форма из 5 блоков уже структурирована
- Chat-wizard без ИИ покрывает guided flow
- ИИ добавляет cost (API), support burden, ошибки парсинга
- ATI-сценарий заточен под **биржу/API**, не под B2B портал одного перевозчика

## 4. Рекомендация

| Решение | Оценка |
|---------|--------|
| Копировать ATI MCP 1:1 | ❌ Избыточно: у ATI это API для агентов, не форма на сайте |
| **Упрощённый MVP (paste → parse)** | ✅ Лучший баланс: даёт 80% пользы Navi/MCP без чата |
| Полный чат-ассистент сейчас | ⏸ Отложить до запроса от реальных заказчиков |
| Skip | ⚠️ Допустимо, если приоритет — стабильность формы, не wow-feature |

**Практический следующий шаг (когда решат делать):**
1. Добавить textarea + «Разобрать» в `customer.js` (режим form, не chat)
2. Backend: JSON schema с полями формы АРМАДА
3. Маппинг `body_type` через существующий `ati-body-types.json`
4. Всегда показывать diff/preview перед apply
5. Не трогать chat-wizard — он остаётся guided fallback без LLM

## 6. Ограничения исследования

- Нет доступа к авторизованному кабинету ATI — **нельзя на 100% исключить** закрытый A/B UI на форме груза для части пользователей.
- help.ati.su не индексирует «ИИ»; поиск по публичным страницам **не нашёл** in-form AI assistant.
- Если Evgeny видел конкретный экран — стоит уточнить: **сайт ATI, CRM (4Logist), или чат-бот (СуперИнтеллект)?**
