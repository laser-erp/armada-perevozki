# АРМАДА — карта проекта (веб `web-preview/`)

> Для людей. Карта «вкладка → что делает → где в коде». Строки плавают при правках,
> поэтому опора — **имя функции** (агент находит его точно). Как работает по сути —
> см. `KNOWLEDGE_BASE.md` (ссылки на §).

## Как устроено (5 файлов)

| Файл | Роль |
|---|---|
| `index.html` | Разметка: все экраны — это `div.screen` с `id`. Каркас, кнопки, поля. |
| `store.js` | «Мозг»: состояние `state`, сохранение, синхронизация с PocketBase, справочники по умолчанию. |
| `app.js` | Проводка (что по какой кнопке), общие хелперы, **расчёт денег** и переключение экранов. |
| `admin.js` | Всё, что видит **администратор** (заявки, ЕТО, биржа, справочники, формы). |
| `driver.js` | Всё, что видит **водитель** (смена, осмотр-ЕТО, заказы — интерфейс-«чат»). |

Переключение любого экрана — одна функция `show(id)` → `store.js:311`.
Список id экранов — в `index.html`: `splash`, `roles`, `driver-login`, `admin-pin`,
`admin`, `admin-create`, `admin-detail`, `admin-catalogs-screen`,
`admin-activity-screen`, `admin-vehicle-card`, `driver`.

## E. Как заказывать правки (рабочее правило)

Чтобы правки шли **только туда, куда указано** (по `TASK_TEMPLATE.md`):

```
Цель: <одна фраза, что должно измениться>
Где: <вкладка из карты> → <имя функции> (файл)
Готово: <как проверить на сайте>
```

Пример: «Цель: на карточке заказа скрыть прибыль для обычного админа.
Где: Карточка заказа → `openDetail()` (`admin.js`). Готово: у не-супер-админа блока прибыли нет».

Правило: правится **одна** названная функция/место, остальное и другие модули не трогаются;
сначала короткий план → «ок» → код.
