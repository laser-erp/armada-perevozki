# План: раздел «Документы» и документооборот АРМАДА

> **Статус:** черновик для согласования (2026-08-30).  
> После ознакомления — дополняем и только потом реализация.  
> **Макет UI:** `/admin-docs-mockup.html` (требует обновления под этот план).

---

## 1. Цель

Один раздел в админке, где:

- юрист работает с **юридическими** текстами сервиса;
- перевозчик ведёт **бухгалтерские** документы по заявкам;
- все печатные формы — на **фирменном бланке** ООО «АРМАДА» (или бланке фирмы перевозчика с её реквизитами);
- **не** хранятся инструкции для агента, README, GitHub и прочая dev-документация.

Live: https://app.armada.sx/

---

## 2. Термины (зафиксировано — не путать названия)

| Термин | Значение |
|--------|----------|
| **Юридические** | Оферта SaaS, политика ПДн, пакет из 7 документов для юриста — про **программу АРМАДА**, не про перевозку грузов |
| **Бух.доки** | Реальные счета, акты, договоры‑заявки **по заявкам** (архив + выдача заказчику/партнёру) |
| **Письма** | Официальные письма на фирменном бланке (операторы ЭТрН и т.п.) |
| **Конструктор шаблонов** | Окно: слева список документов, справа бланк + редактируемый текст (не отдельная вкладка «Шаблоны для смотрения») |
| **Мы перевозчик** | Фирма везёт груз и выставляет документы **клиенту или партнёру как заказчику перевозки** |
| **Мы заказчик** | Фирма выложила заявку на биржу (или иначе заказала перевозку) — документы **от партнёра к нам** |
| **Пакет по заявке** | Кнопка «Скачать всё» **внутри** вкладки «Бух.доки», не отдельный раздел |

## 3. Кто что видит и правит

### 3.1. Оператор сервиса (супер-админ / ООО «АРМАДА» как владелец программы)

- **Юридические** — оферта SaaS, политика, 7 PDF для юриста, полный пакет, КП.
- Правка текстов в **конструкторе** (только документы **платформы**).
- **Бух.доки** своей фирмы как у любого перевозчика — **только документы ООО «АРМАДА»**, не чужих фирм.
- Может **просматривать** «Бух.доки» всех перевозчиков (контроль), но **не правит** чужие шаблоны.

### 3.2. Админ перевозчика (Нечаев, другие фирмы)

- **Своего** раздела «Юридические» (оферта SaaS) **нет**.
- **Конструктор** — только шаблоны **своей фирмы** (договор, договор‑заявка, акт, счёт и т.д.).
- **Бух.доки** — только **своя** фирма: фильтры «Мы перевозчик» / «Мы заказчик».
- **Не видит** и **не правит** шаблоны других перевозчиков.

### 3.3. Заказчик (портал `/z/`)

- Внешний клиент: только **свои** заявки и **свои** документы у **того перевозчика**, в чей портал зашёл.
- Рамочный договор — галочка «Согласен» (MVP; полноценное ЭДО — позже).
- **Не** админка, **не** конструктор шаблонов.

## 4. Структура раздела «Документы» в админке

Полноэкранный экран (как «Активность» / «Тарифы»): **← Назад**, без бокового меню на телефоне.

### Вкладка 1 — **Юридические** (только оператор сервиса)

| № | Документ | Примечание |
|---|----------|------------|
| 01 | Публичная оферта SaaS | Главный договор с клиентом **сервиса** |
| 02 | Политика конфиденциальности (152-ФЗ) | Ссылка с экрана входа |
| 03 | Согласие на обработку ПДн | Портал заказчика |
| 04 | Cookies / localStorage | |
| 05 | Комиссия биржи | Дополнение к оферте |
| 06 | Соглашение о пилоте | |
| 07 | Поручение на обработку ПДн | |
| — | Полный пакет (PDF) | Все 7 в одном файле |
| — | Коммерческое предложение | Не юридический договор |

Источники в репо: `web-preview/legal.html`, `legal-pdf/*` (на проде восстановить/положить).

Открытие: **конструктор** (текст → бланк) + PDF + статус для юриста (черновик / на проверке / утверждён / опубликован) — **этап 2+**.

### Вкладка 2 — **Бух.доки**

**Фильтры:**

- Фирма (у супер-админа — все; у перевозчика — только своя).
- **Мы перевозчик** / **Мы заказчик**.
- Заказчик / партнёр, период, поиск.

**Список:** заявки → документы по заявке (счёт, договор‑заявка, акт, ЭТрН, УПД, счёт‑фактура — по мере внедрения).

**Действия:** Открыть, Email, **Скачать пакет по заявке**.

**Типы документов по заявке (целевой набор):**

| Документ | Когда появляется у заказчика / в архиве |
|----------|----------------------------------------|
| Счёт на оплату | После заявки (есть в коде) |
| Рамочный договор | При первой работе с перевозчиком (есть) |
| Заявка на перевозку | После назначения водителя и ТС (есть) |
| Договор‑заявка | После назначения / «Забрать» с биржи (есть) |
| ЭТрН | Пилот (есть) |
| Акт выполненных работ | **После закрытия заявки** перевозчиком (есть) |
| Счёт‑фактура | **Создать** — для фирм с НДС |
| УПД | **Создать** — альтернатива акт + счёт‑фактура |

### Вкладка 3 — **Письма**

- Пустой фирменный бланк.
- Письма операторам ЭТрН (Контур, Астрал).
- «Новое письмо» — текст в бланк.

Файлы: `docs/operator-letters/`, `armada-letterhead.css`.

## 5. Конструктор шаблонов (п. 1 по порядку реализации)

```
┌──────────────────┬─────────────────────────────────────┐
│  Список документов│  Просмотр на фирменном бланке      │
│  (только своя     │  + кнопки: Редактировать / Сохранить│
│   фирма)          │  + Печать / PDF                    │
└──────────────────┴─────────────────────────────────────┘
```

**Правила:**

- Человек правит **текст** (оферта, договор, письмо) или **поля формы** (счёт, УПД).
- Программа подставляет: шапку/подвал бланка, реквизиты из «Наша фирма», данные из заявки.
- Госформы (счёт‑фактура, УПД) — **структура фиксирована**, меняются в основном **данные**, не произвольный текст.

**Два типа тела документа:**

1. **Юридический текст** — оферта, политика, письмо (юрист правит слова).
2. **Регламентированная форма** — счёт, УПД, ЭТрН (поля из заявки + шаблон).

**Доступ к списку слева:**

| Кто | Список в конструкторе |
|-----|------------------------|
| Оператор сервиса | Юридические платформы + шаблоны **своей** фирмы‑перевозчика |
| Перевозчик | Только шаблоны **своей** фирмы |

## 6. Перевозчик и как заказчик — документы

Любая **фирма‑перевозчик** может быть в одной заявке:

- **перевозчиком** (везёт, выставляет счёт/акт);
- **заказчиком перевозки** (биржа: свой парк занят → партнёр везёт).

### 6.1. Обычный заказ (мы перевозчик)

- Клиент с рекламы / портала `/z/`.
- Договор‑заявка: **клиент ↔ наша фирма**.
- Счёт, акт: **мы → клиент**.
- В «Бух.доки»: **Мы перевозчик**.

### 6.2. Биржа (мы заказчик перевозки)

- Мы выложили заявку, партнёр нажал **«Забрать»**.
- **Договор‑заявка обязательна:** **наша фирма (заказчик перевозки) ↔ партнёр (перевозчик)** — **та же форма**, что с внешним заказчиком.
- Счёт и акт: **партнёр → мы**.
- В «Бух.доки» у нас: **Мы заказчик**; у партнёра: **Мы перевозчик** — **один и тот же** договор‑заявка, две стороны учёта.

### 6.3. Цепочка «клиент + биржа»

На одной логической цепочке возможны **два контура** документов:

1. **Мы ↔ конечный клиент** (мы перевозчик для него с точки зрения денег/документов наружу).
2. **Мы ↔ партнёр** (мы заказчик перевозки на бирже).

Оба контура — в «Бух.доки» с разными фильтрами.

### 6.4. Уже в коде (проверить при реализации)

- При «Забрать» создаётся `transportApp`: `customerCompany*` = фирма заявки, `carrierCompany*` = партнёр (`admin.js`, `confirmClaimExchangeAfterGuard`).
- Договор‑заявка печатается из `order-documents.js` (`buildOrderDocBody`, kind `transportApp`).

## 7. Фирменный бланк

- Единый CSS: `docs/operator-letters/armada-letterhead.css`.
- Шапка: логотип, название, ИНН/КПП/ОГРН, адрес, контакты.
- Подвал: реквизиты, сайт (`app.armada.sx`).
- Для **каждой фирмы‑перевозчика** в шапке — **её** реквизиты из «Наша фирма»; бланк **ООО «АРМАДА»** — для юридических платформы и писем оператора.

**Два оформления тела:**

- **Письмо:** «Кому», подпись директора.
- **Бух/договор:** заголовок документа, таблицы, без «Уважаемые коллеги» где не нужно.

## 8. ЭДО (электронный документооборот) — **не сделано**, план

**Сейчас:** акт и прочее — только просмотр/печать/PDF; рамочный договор — галочка в портале; ЭТрН — пилот/sandbox.

**Целевой процесс подписания акта (и др.) по ЭДО:**

1. Заявка закрыта → документ готов.
2. Перевозчик: «Отправить в ЭДО» (Контур / Диадoc / СБИС — выбор в «Активность»).
3. Контрагент подписывает **в своём кабинете ЭДО** (КЭП).
4. Статус в «Бух.доки»: отправлен → ждёт подписи → подписан.

**Нужно заранее:** договор роуминга/один оператор, КЭП у сторон, ИНН в справочниках, API оператора (заготовка в `admin.js` — `epdOperator`).

**С НДС:** часто УПД вместо пары акт + счёт‑фактура — тот же поток ЭДО.
