# Как писать задачи агенту (Евгений — не программист)

Писать **как пользователь**, не как разработчик. Пути к файлам и код — **работа агента**.

## Скопируйте и заполните

```
Где: prod / staging / телефон
Кто: админ / заказчик / водитель / супер-админ

Шаги:
1) …
2) …
3) …

Проблема: что видите сейчас
Ожидал: как должно быть

Ограничения (по желанию):
- прод не трогать
- только staging
- пуш — нет / напишу «пуш» отдельно
```

## Пример

```
Где: staging, админ, справочник компаний
Кто: супер-админ, фильтр «все кабинеты»

Шаги:
1) снял «наша фирма» у МБН
2) Сохранить — в списке ок
3) вышел и зашёл снова — снова «наша»

Проблема: не сохраняется после повторного входа
Ожидал: без галочки «наша»

Ограничения: прод не трогать
```

## Облачный агент (деплой на сервер)

Одна строка, без истории чата:

```
В laser-erp/armada-perevozki на main открой scripts/ИМЯ.md и сделай по файлу. Прод не трогай.
```

Примеры файлов: `CLOUD_AGENT_DEPLOY_STAGING.md`, `CLOUD_AGENT_STAGING_TLS.md`.

## Что можно не писать

- Имена функций, файлов, «сделай grep»
- Длинные логи (достаточно 10–30 строк или скрин)

## Что агент должен сам

- Уточнить **prod vs staging**, если не сказано (одним вопросом).
- Предложить **1–2 варианта** простыми словами, если путь неочевиден.
- Расследовать баги данных (state API, цикл сохранить → выход → вход) без вашего участия.

## Фразы-ярлыки

| Фраза | Смысл |
|-------|--------|
| прод не трогать | только код/staging, без `deploy-fvds.sh` |
| только staging | проверка на https://staging.app.armada.sx/ |
| пуш | можно коммит и push в GitHub |
| объясни по-человечески | без жаргона в ответе |
| одна задача | не смешивать темы в одном чате |

Технический шаблон для агента (если уже знаете файл): `TASK_TEMPLATE.md`.
