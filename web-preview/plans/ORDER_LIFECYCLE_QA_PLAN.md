# План проверки: жизненный цикл заявки (E2E)

**Назначение:** пошаговая проверка от создания заказчиком до закрытия рейса — статусы, канбан, роли, документы, ЭТрН.  
**Связано:** [ADMIN_PLAN.md](ADMIN_PLAN.md) · [DOCUMENTS_PLAN.md](DOCUMENTS_PLAN.md) · [KONTUR_EPD_PLAN.md](KONTUR_EPD_PLAN.md) · [ARMADA_SX_ORDER_LINKS.md](ARMADA_SX_ORDER_LINKS.md)

**Как пользоваться:** один «сквозной» прогон (сценарий **A**) + выборочно **B–D**. В каждой строке отметка: ☐ OK · ☐ FAIL · ☐ N/A · заметка.

---

## 1. Подготовка

| # | Проверка | Ожидание |
|---|----------|----------|
| 1.1 | Окружение | **Prod** `https://app.armada.sx` или **staging** `https://staging.app.armada.sx` (оранжевая полоса). Записать `APP_BUILD` из консоли (F12). |
| 1.2 | Тестовый space | Кабинет логиста с парком: ≥1 водитель, ≥1 ТС, компания с реквизитами. |
| 1.3 | Роли | **Заказчик:** портал `/z` (или `order.html` с нужным `space`). **Логист:** `/a`. **Водитель:** `/v` (PIN). При необходимости второй браузер/телефон для синхронизации. |
| 1.4 | Биллинг | Тариф не в readonly; `create_order` не заблокирован ([BILLING_SUBSCRIPTION_PLAN.md](BILLING_SUBSCRIPTION_PLAN.md)). |
| 1.5 | ЭТрН (если проверяете документы) | В тарифе `etrnEnabled`; на VPS `armada-api/health` → `epd.configured` (сейчас часто **false** — блок ЭТrН sandbox/заглушка, см. §6). |

**Тестовые данные (пример):** маршрут 2 точки, груз, цена заказчику/перевозчику, ГО ≠ заказчик (отдельные поля shipper), chat_id не нужен для этого сценария.

## 2. Канбан логиста (эталон колонок)

Колонки (`admin.js` / `adminKanbanColumnKey`):

| Колонка | Когда заказ здесь |
|---------|-------------------|
| **Входящие** | Заявка с портала / `order.html`, **нет** назначения водитель+ТС, **нет** выезда (`startOdometer` / `departOdometer` пусто), **не** на бирже |
| **Назначен** | Водитель и ТС назначены, выезд **ещё не** отмечен |
| **На бирже** | `onExchange`, выезд не начат |
| **В работе** | Есть `departOdometer` и/или `startOdometer` (путь / погрузка / рейс / выгрузка) |
| **Закрыт** | `looksClosedOrder` (одометры, км, `closedAt` — см. `app.js`) |

Тексты статусов в списке — `statusText()` (например «Входящая», «Назначен», «В пути · ждём загрузку», «В работе», «На выгрузке · ждём закрытие», «Закрыт»).

## 3. Сценарий A — заказчик → логист → водитель → закрытие *(основной)*

### A1. Создание заявки заказчиком

| Шаг | Кто | Действие | Где | Ожидание |
|-----|-----|----------|-----|----------|
| A1.1 | Заказчик | Открыть портал `/z` или форму `order.html` (ссылка из «Ссылки» / QR) | Браузер заказчика | Форма заявки, выбор типа ТС при необходимости |
| A1.2 | Заказчик | Заполнить маршрут, груз, контакты, отправить | Портал | Успех, номер/подтверждение на экране |
| A1.3 | Заказчик | Обновить список заявок в портале | `/z` | Новая заявка в списке, статус **не** «Закрыт» (см. `customer.js`) |
| A1.4 | Логист | Открыть **Заказы → канбан** | `/a` | Заявка в **«Входящие»**; бейдж/счётчик входящих (если был 0 → +1) |
| A1.5 | Логист | Фильтр «Входящие» (список) | `/a` | Та же заявка видна |
| A1.6 | Супер-админ | Активность / transport-failures | только при сбое | **Пусто**, если заявка создалась (не дублировать в «Активность») |

### A2. Карточка заявки (логист)

| Шаг | Кто | Действие | Ожидание |
|-----|-----|----------|----------|
| A2.1 | Логист | Открыть **Карточку** с канбана | Реквизиты заказчика, маршрут, груз, цены |
| A2.2 | Логист | Заполнить **грузоотправителя** (если ≠ заказчик) | Поля shipper, подсказка про T1 |
| A2.3 | Логист | Задать **цену заказчику / перевозчику** | Строка маржи в карточке (`logistMarginLine`) |
| A2.4 | Логист | **Документы** (печать) | Доступны черновики: заявка, договор-заявка (до закрытия акт — ☐) |

### A3. Назначение водителя и ТС

| Шаг | Кто | Действие | Ожидание |
|-----|-----|----------|----------|
| A3.1 | Логист | На канбане: выбрать водителя + ТС → **Назначить** | Колонка **«Назначен»**; статус «Назначен» |
| A3.2 | Логист | Сохранение на сервер | Синхронизация без ошибки (перезагрузка `/a` — назначение на месте) |
| A3.3 | Заказчик | Портал: карточка заявки | Подтверждение **водитель/ТС/снимки документов** (если включено `publishCustomerDriverDocsConfirm`) |
| A3.4 | Водитель | `/v` → **Заявки** | Заявка в списке **назначенных**, не в «закрытых» |

### A4. ЭТрН (если включено в тарифе)

| Шаг | Кто | Действие | Ожидание |
|-----|-----|----------|----------|
| A4.1 | Заказчик / ГО | T1 (портал или ссылка ГО) | Бейдж «T1…» → после подписи готовность T2 |
| A4.2 | Логист | Канбан / карточка **Подписать T2** | После T1 кнопка активна; до T1 — «T1 · ждём ГО» |
| A4.3 | Водитель | T3 на погрузке, T4 на выгрузке | Бейджи T3/T4 в карточке заказа |
| A4.4 | Логист | Фильтр «Нужна моя подпись» | Заявка в списке, когда T2 pending |

*Если `epd.configured: false` — фиксировать фактическое поведение (sandbox/сообщение) в заметке, не считать FAIL продуктовой логики.*

### A5. Смена и выезд (водитель)

| Шаг | Кто | Действие | Ожидание |
|-----|-----|----------|----------|
| A5.1 | Водитель | **ЕТО** (если требуется политикой space) | Смена открыта |
| A5.2 | Водитель | **Выехал** по заявке | Канбан **«В работе»**; статус «В пути · ждём загрузку» |
| A5.3 | Водитель | **Прибыл на загрузку** + одометр | `startOdometer`, статус «В работе» |
| A5.4 | Логист | Канбан | Колонка **«В работе»** |
| A5.5 | Заказчик | Портал | Статус отражает этап (не «Входящая») |

### A6. Выгрузка и закрытие

| Шаг | Кто | Действие | Ожидание |
|-----|-----|----------|----------|
| A6.1 | Водитель | **Прибыл на выгрузку** + одометр | «На выгрузке · ждём закрытие» |
| A6.2 | Водитель | Шаги закрытия (км, заправка при необходимости, **T4** если ЭТrН) | `looksClosedOrder` → true |
| A6.3 | Логист | Канбан | **«Закрыт»** (в т.ч. последние 7 дней; «Ещё…» для старых) |
| A6.4 | Заказчик | Портал | **«Закрыт»** |
| A6.5 | Водитель | Заявки | В **выполненных**, не блокирует смену |

### A7. Документы после закрытия

| Шаг | Кто | Документ | Ожидание |
|-----|-----|----------|----------|
| A7.1 | Логист | **Документы → Бух.доки** → заявка | Счёт, договор-заявка, transportApp, **акт** доступен |
| A7.2 | Заказчик | Портал → документы | **Акт** только после закрытия ([DOCUMENTS_PLAN.md](DOCUMENTS_PLAN.md)) |
| A7.3 | Логист | Печать / «Скачать всё» | Реквизиты водителя, ТС, ГО в PDF |
| A7.4 | Логист | Конструктор шаблонов | Подстановка `{{order.number}}` и др. |

### A8. ЕТО / смена (хвост)

| Шаг | Кто | Действие | Ожидание |
|-----|-----|----------|----------|
| A8.1 | Водитель | **Закрыть смену** + одометр на стоянке | Смена закрыта, нет блокирующих открытых заказов |
| A8.2 | Логист | **ЕТО** (если используется) | Смена в архиве, км сходятся с заказом |

## 7. Синхронизация и регрессии (коротко)

| # | Проверка | Ожидание |
|---|----------|----------|
| 7.1 | Два клиента: логист + водитель | После назначения водитель видит заявку ≤ несколько сек (PB sync) |
| 7.2 | Перезагрузка `/a` и `/z` | Статус и колонка канбана те же |
| 7.3 | Ложное закрытие портальной заявки | Без выезда заявка **не** в «Закрыт» (`healPhantomPortalClose`) |
| 7.4 | `dataEpoch` / push | После «Назначить» изменения на сервере (`/armada-api/state` — для тех.проверки) |

## 9. Известные ограничения (не путать с FAIL)

- **ЭТrН боевой обмен** — зависит от ключей Контура и `epd.configured` ([KONTUR_EPD_PLAN.md](KONTUR_EPD_PLAN.md)).
- **Входящая ЭТrН → автозаявка** — этап **3b**, не в этом чеклисте.
- **Счёт-фактура / УПД** — ⬜ ([DOCUMENTS_PLAN.md](DOCUMENTS_PLAN.md)).
- **Staging / prod** — общие данные API; различие только UI-сборка и баннер staging.
